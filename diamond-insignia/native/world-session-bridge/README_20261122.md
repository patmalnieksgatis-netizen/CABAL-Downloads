The bridge calls \`AcquireExclusive\` **before dereferencing any WorldSvr pointers**. A future real implementation MUST guarantee that both memory regions are readable and the registry prevents disconnect, character switch or conflicting save until \`ReleaseExclusive\`. It compares the \`+0xE8\` pData pointer and account/character fields against independently trusted registry identity and generation. A RAII guard holds the session/character lock through the entire existing ODBC/CommitGate transaction. The bridge cannot be enabled without an authority implementing real session liveness.

**Strict clone DB guard:** \`DiamondLabOdbcBackend\` still refuses all databases except \`Server01_DiamondLab\` and synthetic UserNum=900001. It is **not** a production player-wallet/inventory bridge.
